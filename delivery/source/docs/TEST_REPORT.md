关键可验收结论：

1. **单活跃 WebGL 场景**：三维页面 `canvas` 数量均为 1；非三维页面为 0（首屏未加载 three.js）。
2. **细胞热标完整**：神经元 4 个（胞体 / 树突 / 轴突 / 髓鞘）、白细胞 3 个，
   均在默认机位下渲染并投影到正确位置（`data-behind="false"`）。
3. **器官取景有效**：大脑、心脏、脾脏三页均能看到清晰的器官形态（截图见 `docs/screenshots/`）。
4. **无白屏**：在 WebGL 不可用的浏览器会话中，页面仍渲染出 24–28 个可交互元素，
   舞台内给出「当前浏览器不支持 WebGL」的明确说明，其余内容（结构清单、知识卡、来源、导航）可用。

### 4.1 验收过程中发现并修复的真实缺陷

| # | 缺陷 | 现象（实测） | 修复与验证 |
|---|---|---|---|
| 1 | 无限更新循环 | 点击「聚焦」后控制台报 `Maximum update depth exceeded`，整页崩溃，`canvas` 归零 | `useAtlasComposition` 返回的数组引用改为 memo 化；上报回调改用 ref；同结构上报去重。修复后 15 页重跑，error 数为 0 |
| 2 | 缺少错误边界 | 前一次会话中 WebGL 上下文丢失后，三个页面「可交互节点 = 0」（白屏） | 新增应用级与舞台级错误边界。修复后同一环境下页面仍有 24–28 个可交互元素 |
| 3 | 神经元热标缺失 | 默认机位下 DOM 中只有 3 个热标（髓鞘被裁掉） | 改为自研投影式热点层（普通 DOM + 每帧投影），并加入确定性取景归一化。修复后为 4 个热标且位置正确 |
| 4 | 器官取景过远 | 器官页中器官在画面里极小 | 用子树真实几何锚点估算范围取景 + 局部隔离 + 抵消查看器的整体拟合 |

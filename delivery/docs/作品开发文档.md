# BodyDay（身体的一天）· 作品开发文档

**赛道**：2026 辽宁省大学生科普设计大赛 · 非医类健康科普赛道 · 第 4 组（健康科普小程序、H5 交互式和电子杂志设计）

**作品形态**：H5 交互式网页作品（单页应用，15 个可独立直达页面）

**作品名称**：BodyDay · 身体的一天

---

## 一、需求分析

### 1.1 问题

面向大众的健康科普长期存在两个断层。第一是**尺度断层**：公众熟悉的科普材料要么停在「人体有多少块骨头」的宏观层面，要么直接跳到细胞名词表，中间「器官—组织—细胞—细胞结构」的层级被压缩成一张平面插图，读者很难建立空间上的连续感。第二是**关系断层**：许多通俗材料把「器官里有这种细胞」当作默认结论，不做区分，结果制造出「心脏生产白细胞」「脾脏制造免疫细胞」这类流传甚广的误解。

对青少年与普通读者而言，更实际的需求不是记住更多名词，而是理解**结构与功能的对应关系**，并把它接到可执行的健康行为上——这正是国家卫健委《中国公民健康素养——基本知识与技能（2024 年版）》所强调的方向。

### 1.2 目标

BodyDay 的目标是提供一件**可探索、可教学**的交互式科普作品：

1. **双模式**：自由探索（自己决定看哪里）与引导教学（结构化课程带着走），两者共用同一套模型舞台，而不是两套割裂的体验。
2. **跨尺度连续**：从一具可转动的完整人体出发，逐层进入系统 → 器官 → 细胞 → 细胞内部结构，全程显示当前尺度与上级路径，并可原路返回。
3. **关系语义化**：结构隶属、功能相关、循环输送、疾病语境分别登记并显式展示，明确拒绝「所有器官 → 任意细胞」的自动兜底关系。
4. **健康科普落地**：每条路线都回答「这个结构如何工作 → 与什么健康行为或常见问题相关 → 可以采取什么有依据的认识」，并逐条标注来源。
5. **科学边界清晰**：明确声明模型为科普示意、不按真实比例、标注点未做逐点配准，作品不构成医疗建议。

### 1.3 目标用户与场景

- 中学生与大学生：具备基本的生物常识，愿意自己动手探索，但不满足于静态插图。
- 科普教师与家长：需要一个可演示、可提问、可检验理解的现成教具。
- 使用场景：桌面浏览器（课堂演示、自主学习）与手机浏览器（碎片时间浏览）。

### 1.4 功能需求（P0 / P1）

**P0（必须实现）**：完整人体层 / 器官层 / 细胞层三层模型；科学知识卡；可信的器官与细胞 ID 映射；教程引导与交互完成判定；至少 3 个有效测验情境；学习反馈（含机制解释与来源）；当前尺度与上级路径显示；加载 / 错误 / 重试 / 资源不可用状态；移动端操作；减弱动态偏好支持；中文主界面。

**P1（尽量实现）**：跨器官知识关联浏览、学习进度与已发现结构图谱、内容来源与术语解释。

**明确不做**：原「寝室生活模拟」场景、人物漫游、虚构医学参数预测、医疗诊断、从零重建全部人体器官、全器官全细胞强行覆盖、AI 聊天、用户登录与复杂后端、无授权模型拷贝、用截图冒充实时交互。

## 二、竞品对比

对比对象限定在「公开可访问的人体/细胞科普交互作品与开源查看器」，评价维度为本作品需要解决的四个断层。

| 对象 | 尺度连续 | 关系语义 | 双模式教学 | 许可与可溯源 | BodyDay 的取舍 |
|---|---|---|---|---|---|
| BioDigital / 商业解剖应用 | 强（商业体渲染） | 弱（关系多为并列） | 弱（偏浏览） | 闭源、需授权 | 不采用：授权与成本不可控；本作品只需示意级结构 |
| Zygote Body 等在线人体 | 中 | 弱 | 无 | 闭源 | 参考其「层级 + 隔离」交互思路 |
| OpenStax 等开放教材插图 | 无 3D | 中 | 有章节 | CC BY | **采用为知识来源**（S01–S05、S19），但插图不满足交互需求 |
| Vanatome（开源人体查看器） | 强（真实图谱） | 无 | 无 | 代码 MIT / 资产 CC BY-SA 4.0 | **采用为其人体与器官层渲染基础**，自行补齐关系、教学与视觉系统 |
| 各类开源细胞模型仓库 | 仅细胞层 | 无 | 无 | 多为许可不明 | **不采用模型**，改为自研程序化细胞几何 |
| 医学教育类 App/游戏 | 有 | 中 | 有测验 | 闭源 | 参考「交互完成判定 + 即时反馈」的教学结构 |

**结论**：现有作品在「单点能力」上往往很强，但**同时具备跨尺度连续、关系语义化、双模式教学与可溯源许可**的作品很少。BodyDay 的定位不是做一个更强的人体查看器，而是把成熟的解剖数据重新组织成一件**以关系与尺度为核心的科普教学作品**。

## 三、概要设计

### 3.1 总体结构

作品为单页应用（SPA），使用 HashRouter 提供 15 个可独立直达的页面，共享一个稳定外壳（品牌、模式切换、全局入口）与三个尺度的舞台。

```
封面 ─┬─ 使用向导（尺度练习）
      ├─ 自由探索 ─┬─ 人体总览 ─ 人体系统（11 系统）
      │            └─ 器官探索（大脑/脾脏/心脏） ─ 细胞探索（神经元/白细胞）
      └─ 引导教学 ──── 神经科普课 / 免疫科普课 / 循环关联课
交叉入口：科学关系图 · 学习总结 · 封底/关于
```

### 3.2 跨尺度模型与转场

尺度轴定义为 **人体 → 系统 → 器官 → 组织 → 细胞 → 结构** 六级。作品明确区分两种连续性：

- **同模型内的空间连续**：人体 → 器官，是在同一个解剖模型中把镜头推进并隔离该器官，空间关系真实保留。
- **跨模型的语义连续**：器官 → 细胞，是两个不同模型之间的切换。作品用**尺度轴遮罩**交代「尺度变了、模型换了」，并**不声称**几何坐标严格配准。

### 3.3 数据设计

见第五章「核心关系数据」。全部内容为纯数据，可逐条核对与扩展。

### 3.4 视觉设计

采用「暖纸 + 解剖图册」体系：暖白纸面（`#F7F5F1`）与近黑墨色（`#1A1917`），展示层用衬线（系统中文字体栈），正文用系统无衬线，标签用等宽；界面直角优先、以细线分隔，视觉主角始终是三维对象本身；彩色只承担解剖系统与尺度的语义，不作装饰。禁止霓虹科技大屏、玻璃拟态与无意义粒子。

### 3.5 动效设计

只保留五类有解释力的动画：Hover（可否操作）、Selection（当前选中）、Route（进入/返回）、Camera（空间移动）、Scale（尺度变化）。判据是「删掉这段动画，用户是否更难理解我在哪一层 / 这是不是同一个对象」。`prefers-reduced-motion` 下全部降级为瞬时。

| 三维层 | `src/three/` | 人体/器官舞台、细胞舞台、程序化几何、按需加载入口 |

### 4.2 关键接口

**三维舞台协议**（`AtlasStageProps` / `ModelStageProps`）

| 能力 | 参数 | 说明 |
|---|---|---|
| 加载 | `bundles` | 按解剖系统懒加载；失败可 `retry` |
| 选中 | `selectedStructureId` + `onSelectStructure` | 受控；结构 ID 必须是模型内真实存在的 ID |
| 元数据 | `onStructureInfo` | 回传真实结构名、类型、所属系统与映射到的作品实体 |
| 聚焦 | `focusRequestKey` | 变化时推进镜头；被拒绝时通过 `onFocusRejected` 明确告知原因 |
| 取景 | `frameStructureId` + `autoCameraFrame` | 由子树真实几何锚点推导入场机位 |
| 隔离 | `isolationMode`（`selected` / `parent` / `parent-context`） | 器官独立视图与层级观察 |
| 复位 | `resetViewKey` | 回到入场机位 |
| 释放 | 组件卸载 | 路由级切换，同一时刻只有一个活跃 WebGL 场景 |

## 五、核心关系数据

作品共登记 **14 条**科学关系，覆盖 **5 种**关系类型。所有关系端点均为已登记实体，且每条关系都写明自身的科学语义与依据来源。

| 关系类型 | 含义 | 示例 |
|---|---|---|
| `part_of` 结构隶属 | 一种结构在解剖层级上从属于另一种 | 心脏 → 循环系统；脾脏 → 淋巴系统 |
| `functional` 功能相关 | 功能上相互关联，不表示「拥有」 | 脾脏 → 白细胞（免疫应答场所，白细胞主要在骨髓生成） |
| `circulates_through` 循环输送 | 通过循环被运输到该处，**不代表在此生成** | 心脏 → 白细胞（心脏提供动力，不生成白细胞） |
| `disease_context` 疾病语境 | 仅在明确疾病机制下成立 | 高血压 → 心脏负担；睡眠不足 → 认知功能 |
| `extends_to` 尺度延伸 | 从当前尺度向下进入更小尺度 | 大脑 → 神经元（神经组织相关细胞） |

**三条必须说准确的关系**（同时是自动化测试的断言对象）：

1. 「大脑 → 神经元」：表示脑的神经组织中含大量神经元且类型多样，**不表示**某个脑区只有一种神经元。
2. 「脾脏 → 白细胞」：是**功能相关**，脾脏是免疫细胞聚集与应答的重要场所之一；白细胞主要在骨髓生成。
3. 「心脏 → 白细胞」：是**循环输送**，白细胞随血液流经心脏并被输送到全身；心脏提供动力，**不生成**白细胞。

作品**不使用**任何自动生成的兜底关系；器官到细胞只允许上述三条明确登记的组合（由测试强制）。

## 七、技术创新

1. **双模式共享同一模型舞台**
   自由探索与引导教学不是两套页面，而是同一套舞台的两种驱动方式。课程步骤直接作用于模型
   （转动、聚焦、选中部件、跨尺度进入），系统能检测交互是否真的完成，而不是按钮翻页。

2. **关系类型语义化的知识模型**
   用「结构隶属 / 功能相关 / 循环输送 / 疾病语境 / 尺度延伸」五种显式类型替代含糊的「有关系」，
   并以自动化测试禁止兜底关系生成。这在科普作品中较少见，直接针对真实存在的科学误解。

3. **尺度交代式跨尺度转场**
   在同模型内推进镜头（人体 → 器官）与在模型之间切换（器官 → 细胞）被明确区分：
   后者以尺度轴遮罩交代「换了模型、尺度变了」，避免让观众误以为是对同一几何连续放大。

4. **程序化细胞几何（原创）**
   神经元与白细胞的三维形态完全由本工程按确定性伪随机参数生成，包含胞体、多级树突、
   长轴突、分段髓鞘、分叶核等结构，并暴露与领域实体一一对应的可选中部件。
   这样既规避了第三方细胞模型的许可风险，也保证了部件与视觉的可控性。

5. **取景归一化与投影式热点的工程处理**
   细胞模型各向异性强，作品用确定性变换把模型装进统一可视半径，保证默认机位能完整取景；
   结构热点采用「普通 DOM + 每帧投影」实现，既保证可点击、可 Tab 聚焦、可被读屏朗读，
   也避免依赖第三方库的隐式剔除导致标注消失。

6. **错误边界与降级优先的设计**
   浏览器不支持 WebGL、上下文丢失、模型加载失败三类真实故障都有明确的界面说明与重试入口，
   页面其余内容保持可用；作品把「不白屏」当作硬性验收项，并在真实浏览器中验证过。

7. **数据可信度自动化护栏**
   41 项单元测试覆盖来源完整性、实体与关系一致性、课程步骤可达性、测验有效性
   （含「不得考数字记忆」）与细胞几何取景，把「不许造假」从口号变成可执行的检查。

## 九、安装与使用

### 9.1 环境要求

Node.js 18 以上（开发使用 v24.15.0），现代浏览器（需支持 WebGL）。

### 9.2 安装与运行

```bash
cd body-day
npm install          # 或 npm ci
npm run dev          # 开发模式 → http://localhost:5173/
npm run build        # 生产构建，产物在 dist/
npm run preview      # 预览生产构建 → http://localhost:4173/
npm run test         # 单元测试
npm run lint         # 代码检查
```

### 9.3 部署

构建产物为纯静态文件，可直接部署到任意静态托管。使用 HashRouter，
**无需服务端重写规则**，刷新与直接粘贴链接均可正确恢复视图。

可选环境变量：`VITE_BODYDAY_ATLAS_URL` —— 指向与官方同版本的解剖 atlas 目录，
用于部署环境无法访问外网时切换到自建镜像。

### 9.4 操作说明

| 输入 | 行为 |
|---|---|
| 左键拖动 / 单指拖动 | 旋转模型 |
| 滚轮 / 双指捏合 | 缩放 |
| 右键 / 双指平移 | 平移（人体层支持右键结构菜单） |
| 单击结构或热点 | 选中，右侧显示对应知识 |
| 空白处单击 | 取消选中 |
| Tab / Enter / Space | 键盘遍历与选中结构 |
| 系统「减少动态效果」 | 全部转场与镜头动画变为瞬时 |

41 项自动化测试与 15 页真实浏览器验收。

**主要技术难点与处理**：

1. 解剖数据与科普叙事之间的落差 —— 通过「子树真实几何锚点取景」与「关系类型化」解决；
   过程中还发现 atlas 中的器官节点多为**无自身几何的分组节点**，直接聚焦会被拒绝，
   因此改为按子树几何范围取景并主动抵消查看器的整体拟合。
2. 三维与首屏体积的冲突 —— 通过按需加载把三维运行时拆成独立分块，使 5 个非三维页面
   完全不承担三维体积（实测这些页面 canvas = 0）。
3. 多模型切换的稳定性 —— 采用路由级单活跃场景、应用级与舞台级错误边界，
   并用「尺度遮罩」明确交代换模型这件事。

**不足与后续方向**：移动端真机验收与真实 GPU 性能数据待补；组织层（tissue）目前以文字与上层结构呈现，
不做体渲染；若时间允许，可扩展胰腺 → 胰岛 β 细胞路线（需先获得许可明确的专用细胞模型，
在此之前不使用普通动物细胞冒充）；全局搜索与模型对比留作后续能力。

**科学边界**：BodyDay 是健康科普作品，**不构成医疗建议**；三维模型为科普示意，不按真实比例，
标注点未与模型做逐点配准；所有关键知识均标注来源编号，完整来源表见作品「关于」页与
`SOURCES.md`（19 条，均于 2026-10-14 实测可达性）。

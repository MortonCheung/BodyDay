# 一、需求分析

## 1.1 问题

面向大众的健康科普存在两个断层。一是**尺度断层**：常见材料要么停在「人体有多少块骨头」的宏观层面，要么直接跳到细胞名词表，中间「器官—组织—细胞」的层级被压成一张平面插图，读者难以建立空间连续感。二是**关系断层**：不少通俗材料把「器官里有这种细胞」当作默认结论，由此产生「心脏生产白细胞」「脾脏制造免疫细胞」这类误解。

对青少年与普通读者而言，更实际的需求是理解**结构与功能的对应关系**，并把它接到可执行的健康行为上。这与《中国公民健康素养——基本知识与技能（2024 年版）》强调的方向一致。

## 1.2 目标

BodyDay 提供一件**可探索、可教学**的交互式科普作品：

1. **一个工作台**：中央始终是同一具可转动的真实三维人体，右侧信息栏随当前选中联动。用户不必在页面之间跳转，就能从人体一路看到细胞。
2. **跨尺度连续**：从完整人体出发，逐层进入系统 → 器官 → 细胞，全程可原路返回；尺度变化由**镜头位置与右栏内容**表达，不换页面外壳。
3. **关系语义化**：结构隶属、功能相关、循环输送、疾病语境、尺度延伸分别登记并显式展示，拒绝「所有器官 → 任意细胞」的自动兜底关系。
4. **健康科普落地**：每条路线回答「这个结构如何工作 → 与什么健康行为或常见问题相关」，并逐条标注来源。
5. **科学边界清晰**：声明模型为科普示意、不按真实比例、标注点未做逐点配准，不构成医疗建议。

## 1.3 目标用户与场景

- 中学生与大学生：具备基本生物常识，愿意自己动手探索，不满足于静态插图。
- 科普教师与家长：需要可演示、可提问、可检验理解的现成教具。
- 使用场景：桌面浏览器（课堂演示、自主学习）与手机浏览器（碎片时间浏览）。

## 1.4 功能需求（P0 / P1）

**P0（必须实现）**：一个空间工作台（中央唯一真实三维人体 + 右侧随选中联动的信息栏）；启动封面闸门（真实字节进度 → 模型就绪 → 手动进入）；人体层 / 系统层 / 器官层 / 细胞层四个尺度的模型；结构科学与健康知识卡；可信的结构 ID 映射；模型驱动的点选 / 聚焦 / 隔离 / **滚轮驱动的逐层真实拆解**；器官 → 细胞的跨尺度链路；加载 / 错误 / 重试 / 资源不可用状态；移动端操作；减弱动态偏好支持；中文主界面。

**P1（尽量实现）**：右栏上的关系浏览（随选中联动）、学习进度与已发现结构记录、内容来源与术语解释。

**明确不做**：原「寝室生活模拟」场景、人物漫游、虚构医学参数预测、医疗诊断、从零重建全部人体器官、全器官全细胞强行覆盖、AI 聊天、用户登录与复杂后端、无授权模型拷贝、用截图冒充实时交互。

## 1.5 竞品对比与取舍

对比对象限定在「公开可访问的人体 / 细胞科普交互作品与开源查看器」，评价维度为本作品需要解决的四个断层。

| 对象 | 许可 | BodyDay 的取舍 |
|---|---|---|
| Human Atlas（`ashemag/human-atlas`） | 代码 MIT（© 2026 ashemag）；模型 BodyParts3D（CC BY 4.0） | 法律上可复用；因渲染栈与 three 版本不兼容、模型约 33 MB、ID 体系不同，本轮未移植（见 3.11） |
| Anatomy（`thebuggeddev/anatomy`） | 未确认（仓库无 LICENSE） | 未复制；其九器官名单仅作目标能力参考 |
| Vanatome / Z-Anatomy | 代码 MIT；资产 CC BY-SA 4.0 | 采用其同源 Z-Anatomy 整具人体资产作为数据基础；其查看器封装因不支持真实网格位移而移除 |
| BioDigital 等商业解剖应用 | 闭源、需授权 | 不采用：授权与成本不可控 |
| OpenStax 等开放教材插图 | CC BY | 采用为知识来源（S01–S05、S19）；插图不满足交互需求 |
| 各类开源细胞模型仓库 | 多为许可不明 | 不采用模型，改为自研程序化细胞几何 |

**结论**：同时具备跨尺度连续、关系语义化、可教学与可溯源许可的作品很少。BodyDay 的定位是把成熟的解剖数据重新组织成一件以关系与尺度为核心的科普教学作品，让用户在一个工作台内完成从人体到细胞的连续观察。

# 二、概要设计

## 2.1 总体结构与产品形态

作品为单页应用（SPA），使用 HashRouter 提供 **16 个可独立直达的页面**（含封面与封底，逐页清单见 3.9）。整体形态是**一个空间工作台**：

- 中央始终是**同一具真实三维人体**（本作品自建的 React Three Fiber 舞台，Three.js r186 + R3F 9 + Drei 10，直接加载随包发布的 Z-Anatomy 整具人体 GLB）；
- 桌面版式为**三栏**：左操作栏（240–280px）/ 中央三维（`minmax(0,1fr)`）/ 右信息栏（300–360px）；
- **左操作栏只在整具人体可被筛选的页面出现**（人体探索、人体总览、系统页），内容是「系统筛选」按钮组 + 「当前对象」状态，不做科普正文；器官页 / 细胞页 / 器官详解页不出现左栏（不为填空间堆内容）；
- 窄屏（≤1024px）收起左栏回到两栏；≤900px 右栏变为可收起的底部抽屉；
- **主导航只有三项**：**人体探索（`#/explore`）/ 器官详解（`#/detail/heart`）/ 关于（`#/about`）**；左上角 BodyDay 标识回到人体探索。已删除「自由探索 / 引导教学」模式切换与旧的五项层级导航。

**右信息栏只讲当前对象**：顶部标签「当前对象」+ 操作区（当能返回上层时给「返回上一级」、器官详解页给「返回探索」、匹配到已核实器官时给唯一的「查看器官详解 →」）；主体是**通用结构卡**（标题 + 最多一条「大脑 · 额叶」式路径 + 一句真实空间 / 结构说明，字段缺失就整行不渲染）或已登记实体的科普卡；没有选中时给一句简短提示。已删除：`结构类别 / 所属系统 / 上级结构` 的字段堆叠、右侧常驻结构目录、尺度轴、秒级时钟、重复的「取消选中」按钮、多份「继续深入 / 返回」入口。

首页 `/` 先出**完整独立的启动封面闸门**（暖白，与主界面同一视觉语言）：封面内显示模型**真实字节进度**；模型「装配完成 + 首个有效帧」后才出现「进入探索」。入场是**同一个 DOM 节点**从 240×3px 细进度条形变为约 148×44px 的「进入探索」按钮（形变完成前按钮不可点），100% 由真实资源就绪触发，不是假倒计时；**不自动进入、不自动淡出**，进入前整个外壳 `inert` 且不可读屏（状态机 `loading → ready-to-enter → entering → exploring`）。深链 `/body`、`/organ/*`、`/cell/*`、`/detail/*`、`/about` 不经过封面。

## 2.2 功能模块层次

```

  ├─ 空间工作台 ExploreWorkbench
```

## 2.3 跨尺度模型与「尺度的表达」

作品在界面上的尺度分为四层：**人体 → 系统 → 器官 → 细胞**。作品明确区分两种连续性：

- **同模型内的空间连续**：人体 → 系统 → 器官，是在同一个解剖模型中推进镜头 / 换图层 / 隔离该器官，空间关系真实保留；
- **跨模型的语义连续**：器官 → 细胞，是两个不同模型之间的切换；作品不声称几何坐标严格配准，尺度变化由镜头运动本身表达。

> 早期版本曾用一块全屏的「尺度遮罩」交代尺度切换，现已删除；尺度变化改由镜头本身与右栏内容的变化表达。

## 2.4 数据设计

见第三章「核心关系数据」「器官桥接」「通用结构卡」与「领域数据契约」。全部内容为纯数据，可逐条核对与扩展；作品不涉及数据库与后端服务。

## 2.5 视觉与动效设计

采用「暖纸 + 解剖图册」体系：暖白纸面（`#F7F5F1`）与近黑墨色（`#1A1917`）；展示层用衬线（系统中文字体栈），正文用系统无衬线，标签用等宽；界面直角优先、以细线分隔，视觉主角始终是三维对象本身；彩色只承担解剖系统与尺度的语义，不作装饰。禁止霓虹科技大屏、玻璃拟态与无意义粒子。V2 把模型上的**体表 / 骨骼 / 肌肉三个系统统一到暖调（象牙 ↔ 陶土）**，内脏保留资产自带的真实解剖配色；这既与暖白纸面同属一套语言，也属于 CC BY-SA 4.0 要求「标明修改」的一部分（已在 `/about` 与 `public/models/ANATOMY_LICENSE.txt` 说明）。

动效只保留五类有解释力的动画：Hover（可否操作）、Selection（当前选中）、Route（进入 / 返回）、Camera（空间移动）、Scale（尺度变化由镜头运动本身表达）。动效令牌集中在 `src/design/interaction-tokens.css`（`--bd-ease-out` 等）。判据是「删掉这段动画，用户是否更难理解我在哪一层 / 这是不是同一个对象」。`prefers-reduced-motion` 下全部降级为瞬时。

## 3.2 路由解析与页面索引

`src/app/resolveView.ts` 把 URL 解析成一个视图对象（`body` / `system` / `organ` / `cell` / `detail` / `about`），`ROUTES` 与 `PAGE_INDEX`（`src/app/routes.ts`）给出页面路径与索引，`AppShell` 只用**同一个** `<ExploreWorkbench view={view}/>` 渲染所有探索页面，不使用 `<Routes>` 声明多条路由。原因是：若每个页面各自声明一条 Route，路由切换时 React 会卸载并重新挂载舞台，造成「地图先归位、再重新聚焦」式的画面跳动，也会重复加载模型。统一解析路径 → 同一棵组件树只更新 props，**三维场景在整段探索中始终挂载**。

视图解析后，工作台据此决定：是否显示左操作栏（`showControls = !isCell && !entryIsolate`）、是否隔离单个器官，以及入场的聚焦目标与取景方式。

## 3.3 核心关系数据

作品共登记 **14 条**科学关系，覆盖 **5 种**关系类型。所有关系端点均为已登记实体，且每条关系都写明自身的科学语义与依据来源。

| 关系类型 | 含义 | 示例 |
|---|---|---|
| `part_of` 结构隶属 | 一种结构在解剖层级上从属于另一种 | 心脏 → 循环系统；脾脏 → 淋巴系统 |
| `functional` 功能相关 | 功能上相互关联，不表示「拥有」 | 脾脏 → 白细胞（免疫应答场所，白细胞主要在骨髓生成） |
| `circulates_through` 循环输送 | 通过循环被运输到该处，不代表在此生成 | 心脏 → 白细胞（心脏提供动力，不生成白细胞） |
| `disease_context` 疾病语境 | 仅在明确疾病机制下成立 | 高血压 → 心脏负担；睡眠不足 → 认知功能 |
| `extends_to` 尺度延伸 | 从当前尺度向下进入更小尺度 | 大脑 → 神经元 |

**三条必须说准确的关系**（同时是自动化测试的断言对象）：

1. 「大脑 → 神经元」：表示脑的神经组织中含大量神经元且类型多样，**不表示**某个脑区只有一种神经元。
2. 「脾脏 → 白细胞」：是**功能相关**，脾脏是免疫细胞聚集与应答的重要场所之一；白细胞主要在骨髓生成。
3. 「心脏 → 白细胞」：是**循环输送**，白细胞随血液流经心脏并被输送到全身；心脏提供动力，不生成白细胞。

作品不使用任何自动生成的兜底关系；器官到细胞只允许上述三条明确登记的组合（由测试强制）。

## 3.4 器官桥接：`organBridge` 人工核对表

`src/integrations/organBridge.ts` 是一张**人工核对表**，禁止字符串模糊匹配：每条记录包含位置结构名、目标器官、`certainty`（`verified` / `needs-review`）与依据说明。

- **已核实（verified）**：`heart` → heart；`cerebrum` / `cerebellum` / `brainstem` → brain；`lungs` → lungs；`spleen` → spleen。
- **未核实（needs-review，`target: null`，界面不显示入口）**：liver、kidneys、pancreas、eyeball、intestine、skin。

因此当前可进入的器官详解页是**心、脑、肺、脾**四个。映射表由测试校验：未核实项必须 `target: null`；`spleen` 明确映射到自身；`pancreas` 单独列为 needs-review，**绝不把脾脏映射成胰腺**。

## 3.5 通用结构卡

模型里有大量未登记中文名的真实解剖节点，本作品只对少数结构编写了经核对的科普内容。对其余节点，右栏用 `src/domain/structureCard.ts` 的纯函数生成一张只讲事实的卡：`structureCardPath` 给出「上级 · 当前」式路径（如「大脑 · 额叶」），`structureCardPlacement` 给出「位于 X 系统。」式的一句空间 / 结构说明；只用 GLB 中真实存在的字段出卡，字段缺失即整行不渲染，不编造作用或健康关系。

## 3.6 关键技术：自建三维舞台与真实拆解

**自建舞台而非第三方查看器**。V2 从渲染路径移除了 `@vixotic/vanatome-react`：其公开 API 只提供 select / focus / isolate / reset / visibleLayers，没有网格位移入口，无法实现真实拆解。作品改由自建的 React Three Fiber 舞台 `FullBodyStage` 直接加载整具人体 GLB，从而能拿到每个真实网格并逐组位移。

**镜头取景**。atlas 元数据里的 `position` 只是**兜底锚点，并不在渲染坐标系中**；早期用它在外部推算机位会把相机放进网格内部，导致画面全黑。现在的做法是「选中并请求聚焦目标结构」，由舞台遍历真实网格算包围盒决定机位：

- 全身取景用 `body-shell`（运行时实测 233 个网格）；
- 系统取景用该系统的**根结构**（如 `nervous-system`），运行时从已加载清单中取；
- 器官取景用 `cerebrum` / `heart` / `spleen`。

**真实几何拆解**。舞台读取 GLB 的 `extras`（`anatomyId` / `anatomyParentId` / `anatomySystem`），按可位移结构组对**真实网格位置**做径向平移，并按解剖系统分层（regional-anatomy=0、muscular=1、skeletal=2、cardiovascular/lymphatic/respiratory/digestive/urinary=3、nervous/endocrine/reproductive=4，每层额外位移 = 人体包围球半径 × 0.17）；体表外壳 `body-shell` 在进度 0→0.4 渐进隐去，≥0.4 后不可见并被移出射线层。位移由进度重算、**从不累加**（0→1→0→1 可复现），相机随位移后包围盒联动取景。实测可见网格数：默认 **967**（984 − 17 公开展示过滤）→ 拆解 42% 时 **734**。

**滚轮驱动的拆解**：人体总览未选中时，每格 0.07、钳制 [0,1]，向下拆、向上合；此时原生缩放关闭并在 canvas 捕获阶段拦 `wheel`，只作用于三维舞台，右信息栏滚动不受影响；选中结构后滚轮回交 OrbitControls。桌面端不再显示拆解滑杆（`@media (hover: hover) and (pointer: fine)` 下 `display:none`，触屏保留）。

**公开展示过滤**：默认人体中性化，隐去 `reproductive` 系统（14 个网格）、体表外壳覆盖该区的 2 个分区与 2 个毛发，共 17 个网格，可见网格 984 → 967。

**结构归并与可读名规则**：同一器官下的细分结构归并成该器官一项；能映射到作品实体的结构显示中文名，其余显示**真实解剖英文名**；**内部 ID（如 `body-shell`）一律不展示**。

## 3.7 关键技术：程序化细胞几何（原创）

神经元与白细胞的三维形态完全由本工程按确定性伪随机参数生成，包含胞体、多级树突、长轴突、分段髓鞘、分叶核等结构，并暴露与领域实体一一对应的可选中部件，规避了第三方细胞模型的许可风险。细胞模型各向异性强，作品用**确定性变换**把模型装进统一可视半径，保证默认机位能完整取景；结构热点采用「**普通 DOM + 每帧投影**」实现，保证可点击、可 Tab 聚焦、可被读屏朗读。

## 3.8 加载与就绪链路、返回上下文

**加载 / 就绪事件链路**：舞台在加载 GLB 时上报真实字节进度（`onProgress`），装配完成并渲染出首个有效帧后上报就绪（`onReady`）；启动闸门把二者合成为状态机 `loading → ready-to-enter → entering → exploring`，只有真正就绪才把入口从进度条形变为可点击按钮。

**返回上下文 `ExploreReturnContext`**（`src/features/workbench/returnContext.ts`）：从人体探索进入器官详解前，把当时的选中结构、展开程度与相机状态保存为一份快照（`ReturnSnapshot`）；在器官详解页点「返回探索」时读取快照，恢复进入前的选中 / 展开 / 相机。

**取消选中**：点空白或按 Esc 取消选中并**恢复选中前的相机视角**；选中某一结构时**其余结构淡化而不隐藏**，保留完整人体的空间上下文。

# 六、项目总结

## 6.1 已完成

一个空间工作台（中央唯一真实三维人体 + 右侧随选中联动的信息栏）、**三项主导航**（人体探索 / 器官详解 / 关于，左上角标识回到人体探索）、桌面**三栏版式**与只在可筛选页面出现的**左操作栏系统筛选**、启动封面闸门、四层尺度的模型与内容、**通用结构卡**（只用真实字段出卡）、单一器官详解入口（仅心 / 脑 / 肺 / 脾，来自人工核对的 `organBridge`）、返回上下文恢复（选中 / 展开 / 相机）、真实几何拆解（滚轮驱动，含拆解后仍可点选）、选中「高亮 + 其余淡化」与取消选中恢复原视角、默认人体中性化公开展示（隐去 17 个网格）、两条完整贯通链路（脑→神经元、脾脏→白细胞）与一条循环功能关联（心脏↔白细胞）、14 条语义化关系、3 套共 29 步科普脚本与 6 道带解释和来源的检验题（作为内容资产保留）、**90 项自动化测试**与 **16 页**交付。

## 6.2 主要技术难点与处理

1. **解剖数据与科普叙事之间的落差**：通过「取景按真实网格包围盒计算」与「关系类型化」解决；过程中发现 atlas 里器官节点多为无自身几何的分组节点、`position` 也不在渲染坐标系中，因此改为「选中并请求聚焦」、由舞台决定机位。
2. **真实拆解**：第三方查看器封装不支持网格位移，故自建 R3F 舞台直接读取 GLB `extras`，按解剖系统分层对真实网格做径向平移 + 体表外壳渐进隐去；位移由进度重算、从不累加，并用「单组半径上限 + 相机随位移后包围盒联动」双重护栏避免拆解时人体飞出画面。
3. **多尺度切换的画面稳定性**：通过「路由不拆分组件树」让三维场景在整段探索中保持挂载，切换页面不重新加载、不重新聚焦。
4. **三维与首屏体积的冲突**：通过按需加载把三维运行时拆成独立分块，使封底 `/about` 完全不承担三维体积（实测该页 `canvas = 0`）。

## 6.3 不足与后续升级

移动端真机验收与真实 GPU 性能数据待补；拆解的产品级视觉分离仍在打磨；组织层（tissue）以文字与上层结构呈现，不做体渲染；未做连续跨尺度转场（现为「镜头推进 + 明确的继续深入入口」）；肾 / 膀胱未新增专题（真实模型里 `urinary` 仅 3 个网格）；中性化属中性化展示而非无性征人体。

**开源整合的止损说明**：Human Atlas 代码为 MIT、模型为 BodyParts3D（CC BY 4.0），法律上可复用，但其渲染栈与本工程 three / R3F 版本不兼容、模型约 33 MB、使用另一套 BodyParts3D 的 ID 体系，按施工手册的 45–70 分钟止损规则**本轮未移植**，因此「同一前视平面二维投影打包」未实现，本作品的展开是分层径向几何分离 + 体表外壳渐进隐去。Anatomy（`thebuggeddev/anatomy`）**许可未确认，未复制**，其九器官名单仅作目标能力参考；器官详解页由本工程已合法分发的 Z-Anatomy 几何 + 自撰中文内容实现。若时间允许，可在许可明确的专用细胞模型到位后扩展胰腺 → 胰岛 β 细胞路线，在此之前不使用普通动物细胞冒充。全局搜索与模型对比留作后续能力。演示视频已按 V2 重录 `delivery/demo/bodyday-v2-walkthrough.mp4`；作品尚未在任何平台提交。

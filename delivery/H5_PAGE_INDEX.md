# BodyDay · H5 页面索引与逐页截图（H5_PAGE_INDEX）

> 赛事要求 H5 交互式作品「页面不少于 10 页（含封面、封底），总页面控制在 20 页以内」。
> BodyDay 按 **16 页**交付（含首页 `/` 与封底 `/about`），每个页面都可独立直达、可单独截图。
>
> 全站只有**一种探索体验**：中央唯一的三维人体（本作品自建 React Three Fiber 舞台渲染的
> Z-Anatomy 整具人体，模型随作品发布在 `public/models/`），右侧一条随选中联动的**「当前对象」**信息栏。
> **主导航只有三项——人体探索（`#/explore`）/ 器官详解（`#/detail/heart`）/ 关于（`#/about`）**；
> 左上角 BodyDay 标识回到人体探索，**不是**第二具人体首页；旧「五项层级导航（身体 / 系统 / 器官 / 细胞 / 关于）」
> 与「自由探索 / 引导教学」双模式**已全部删除**。结构的选择交给模型本身
> （点选、悬停高亮、聚焦、隔离、**滚轮驱动的逐层拆解**，以及「返回上一级」的层级栈）。
> 人体 → 系统 → 器官 → 细胞之间的差别，只体现为**镜头位置与右栏内容的变化**，
> 不换页面外壳、不重挂三维场景。
> 桌面三栏——左操作栏（**240–280px**）/ 中央三维（`minmax(0,1fr)`）/ 右信息栏（**300–360px**）；
> **左操作栏只在整具人体可被筛选的页面出现**（人体探索 / 人体总览 / 系统页），器官页 / 细胞页 / 器官详解页**不出现**左栏。
> ≤1024px 收起左栏回到两栏，≤900px 右栏变为可收起的底部抽屉。
> **2026-10-18**：入口为**同节点形变**（同一个 DOM 节点从 240×3px 细进度条形变为约 148×44px「进入探索」按钮，
> 形变完成（`data-settled="true"`）前 `disabled`）；右信息栏只讲**「当前对象」**。
> 页面索引的权威来源是 `body-day/src/app/routes.ts` 的 `PAGE_INDEX`，现为 **16 条**；`/about` 页会渲染「作品的可访问页面（16 页）」。
>
> 全部截图由真实浏览器（Chrome for Testing + SwiftShader 软件渲染）在 **1440×900** 视口下对
> **真实运行的开发服务器**抓取（移动端一帧为 390×844，2x），
> 路径见 `delivery/test-evidence/screenshots/`（**14 张真实截图，2026-10-18 重出**，逐张对照见 §2；
> 另有中性化视觉核对截图 10 张在 `…/screenshots/public-presentation/`）。
> 抓取时间：2026-10-18（本机时间）。

## 3. 逐页「该页能做什么」

| 序号 | 该页能做什么 |
|---|---|
| 01 首页 · 启动封面 | 先显示完整独立的启动封面，封面内是真实字节进度；模型真正就绪后，**同一个 DOM 节点**原地形变为「进入探索」（形变完成前不可点）。点击进入后呈现完整人体，可转动、点选与逐层拆解。**不自动进入、不自动淡出**；加载超过 45 秒会提示检查网络并提供「重新加载」。 |
| 02 人体总览 | 不经封面可直接深链进入。桌面显示左操作栏（系统筛选 + 当前对象）；转动完整人体；**用滚轮**向下逐层拆解、向上反向组装（桌面端已移除拆解滑杆，触屏保留）；点模型上的结构即高亮并聚焦（其余结构淡化而非隐藏），右栏「当前对象」随之更新。 |

## 4. 页面计数说明（供评委核对）

- 上表 16 行即 BodyDay 对外声明的 **16 个页面**，首页与封底计入其中；权威来源是 `body-day/src/app/routes.ts` 的 `PAGE_INDEX`（16 条）。
- 其中 03 / 04 / 05（系统）、06 / 07 / 08（器官）、09 / 10（细胞）、12 / 13 / 14 / 15 / 16（探索入口与器官详解）是各自独立的直达路径，
  但**共用同一个工作台组件**，差别只在镜头位置与右栏内容。
  它们不是「换一套外壳的新页面」，也不各自重新加载三维场景。
- 系统页以参数化路由 `/systems/:id` 提供，同一版式下可覆盖全部解剖系统；对外声明的页面数仍为 **16**。
- 关于「20 页以内」：BodyDay 声明为 **16 页**，满足「不少于 10 页」且仍在 20 页上限之内。
- 页面索引同时内置于封底 `/about` 表格中（渲染「作品的可访问页面（16 页）」），可按行逐条核对。

## 5. 截图与录像复现方式

```bash
cd body-day
npm ci                             # 安装依赖（首次）
npx vite --port 5175 --strictPort  # 专用自测端口（不占用日常预览端口 5173）
# 另开终端，在 body-day/ 下运行截图与录像脚本：
node scripts/capture-screenshots.mjs   # 生成真实 PNG 到 delivery/test-evidence/screenshots/
```

脚本用真实浏览器走「封面 → 进入 → 旋转 → **滚轮逐层拆解 / 组装** → 选器官 → 进入器官详解 → 下潜细胞 → 关于」的完整链路，
同一次运行内产出逐页截图；体验录像的原始 webm 写在系统临时目录，再用 `ffmpeg` 转成交付用 mp4。
最终演示成片为 `delivery/demo/BodyDay_最终演示.mp4`（1920×1080，H.264，真实浏览器录屏，≤8 分钟；
**时长以 `delivery/demo/VIDEOCRAFT_PRODUCTION_LOG.md` 的 ffprobe 实测为准**，本文件不写具体秒数）。
旧 `delivery/demo/bodyday-v2-walkthrough.mp4` 属**上一轮版本录像**，已被新成片取代。
整具人体模型随作品发布在 `body-day/public/models/`，
截图与录像**不再依赖外网 CDN**，离线也能复现；细胞页面为程序化几何本地生成，同样无网络依赖。

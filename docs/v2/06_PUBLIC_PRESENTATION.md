## 2. 中性化公开展示：为什么只过滤系统不够

先对真实 GLB 做了几何盘点（`scenes[0].nodes` 平铺，读 `extras.anatomyId` / `anatomySystem` / 网格 POSITION 的 min-max）：

| 项 | 实测 |
| --- | --- |
| 网格总数 / 系统分布 | 984：regional-anatomy 236、nervous 234、skeletal 181、muscular 170、cardiovascular 64、lymphatic 54、**reproductive 14**、digestive 12、endocrine 10、respiratory 6、urinary 3 |
| reproductive 系统网格 | `penile-erectile-tissues-*`（3）、`testes-testis-*`（2）、`epididymides-*`（2）、`prostate`、… 共 14 个 |
| **体表外壳上的对应几何** | `body-shell__Urogenital region.l/.r`（左右各一块，中心 y≈0.758）、`body-shell__Pubic hairs`、另有 `Inguinal region.l/.r` 属正常解剖 |

据此确认任务书的判断：**只隐藏 `reproductive` 系统并不够**，外生殖器形态在外壳上。最终过滤规则（`fullBody.isPublicDisplayExcluded`）同时覆盖系统与外壳区域名，实测隐去 **17 个网格**（14 + 2 + 1），可见网格 984 → 967。

> ⚠️ 实现细节上的坑：three 的 `GLTFLoader` 会用 `PropertyBinding.sanitizeNodeName` 清洗节点名（空格与点 → 下划线），所以 `body-shell__Urogenital region.l` 在运行时是 `body-shell__Urogenital_region_l`。首版按原始名做子串匹配**静默失效**（默认视图仍能看到外生殖器），现已改为归一化后比较，并由单元测试覆盖清洗后的形态。

**真实视觉核对**（多角度截图见交付包 `delivery/test-evidence/screenshots/public-presentation/`）：

| 视角 | 结果 |
| --- | --- |
| 正面 / 左侧 90° / 背面 180° / 右侧 270° | 均无外生殖器细节；体表连续，无空洞或残缺 |
| 骨盆区域近观（3× 放大） | 该处露出真实的肌肉与骨盆结构，呈「解剖切口」观感；不伪造遮挡、也不修改成医学上错误的形态 |
| 拆解 25%（外壳半透明） | 内部结构正常显现，无异常补丁 |
| 拆解 100% | 生殖系统网格不再出现（可见网格 748 = 984 − 236 外壳） |

如实说明：这是**中性化展示**，不是新建一套无性征人体；外壳被移除的是一小块区域，因此近观时会看到该处下方真实的肌肉/骨盆结构。

## 3. 选中语义与相机语义（本轮重新定义的规则）

| 场景 | 行为 |
| --- | --- |
| 人体总览 · 未选中 | 滚轮 = 拆解/组装；拖动 = 旋转；点击 = 选中结构并聚焦 |
| 人体总览 · 已选中 | 选中结构高亮（中性暖白自发光），其余结构淡化但可见；滚轮 = 观察当前结构（原生缩放） |
| 器官页 | 页面级隔离：只显示该器官；滚轮 = 与总览一致（无选中即拆解） |
| 点空白 / Esc / 逐级返回 | 选中清空 + 其余结构恢复 + **相机回到聚焦前的位置与观察目标**（实测误差 0） |
| 手动拖动 | 立刻放弃程序化取景目标，镜头交还给用户，不再互相抢控制权 |

## 5. 仍未解决 / 如实标注

1. **移动端仍只有视口检查**（390×844，无横向溢出），未真机验收；触屏设备保留滑杆，滚轮行为不适用。
2. **真实 GPU 帧率未采集**：本轮所有读数来自 SwiftShader 软件渲染。
3. **连续跨尺度转场未做**：目前是「镜头推进 + 明确的继续深入入口」，不声称 GLB 能连续放大到细胞级。
4. **肾/膀胱**本轮未新增专题（现有真实模型里 urinary 只有 3 个网格，不足以支撑专题），故按任务书要求只保留基础展示能力。
5. 骨盆区域近观时能看到一小块被移除外壳后露出的结构；这是中性化处理的可见代价，已如实记录，未用遮挡物掩盖。

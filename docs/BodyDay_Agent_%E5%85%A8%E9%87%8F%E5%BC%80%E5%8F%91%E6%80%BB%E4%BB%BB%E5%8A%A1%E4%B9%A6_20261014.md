## 3. 产品功能定义（不得自行缩成展示器）

### 3.1 双入口共享引擎

**自由探索模式（P0）**：完整人体/器官系统浏览；点击可操作结构；器官独立查看（聚焦/旋转/缩放/重置/结构标注，具备可靠模型时才开放真实剖切）；以明确按钮或热点进入与其科学相关的细胞；观察细胞与已可识别的亚细胞结构；提供全程面包屑、原路返回、相关知识、知识来源；按需加载而非所有Canvas同时后台工作。

**引导教学模式（P0）**：同样的人体/器官/细胞模型作为舞台，由引导状态机组织“目标→交互观察→机制解释→1~3题反馈→章节小结”。课程步骤必须指向实际模型/结构、可检测是否完成交互，不是PPT按钮翻页。支持跳过/重试/返回探索、持续记住章节进度（本地存储足够，不要为此搭后端）。

**推荐路线：**
- `大脑 → 神经元 → 胞体、树突、轴突`，主题“神经信号与神经系统健康”（默认第一条端到端验证和主打演示）。
- `脾脏 → 白细胞 → 可合法展示的细胞结构`，主题“免疫细胞如何参与防御”（脾脏与白细胞是功能关联，具体细胞类型需严谨描述）。
- `心脏 → 循环血液 → 白细胞`，主题“血液循环如何运输细胞/物质”，**不宣称心脏生产白细胞**，可复用相同白细胞展示且标签显式写“循环功能关联”。
- 可扩展 `肌肉→肌细胞→运动与健康`、`胰腺→胰岛β细胞→血糖管理`，但当缺少有许可证的专门β细胞模型时使用清晰标注的科学示意图或不启用细胞3D深潜，禁止用普通动物细胞冒充专用细胞。

**科学关系至少3类**：`part_of`（结构隶属）、`functional`（功能相关）、`disease_context`（明确疾病机制）；还可以有`circulates_through`等类型。关系永远应显示自己的科学语义，不能默认视为“器官内部一定拥有该细胞”。例如白细胞在心血管系统中属于循环运输，在脾脏属于免疫活动，在胰腺只有具体条件下才谈自身免疫机制。不能使用自动生成的“所有器官→任意细胞”兜底。

### 3.2 其他 P0/P1 功能

P0：完整人体层/器官层/细胞层；科学知识卡；可信的器官/细胞ID映射；教程引导；至少3个有效测验情境；学习反馈；当前尺度和上级路径；完整加载/错误/重试/资源不可用状态；移动端操作；减弱动态偏好；中文主界面。

P1：跨器官知识关联浏览、全局搜索（本地离线索引即可）、学习进度/已发现结构图谱、模型对比（只比较确实有对应资产的内容）、内容来源和术语解释。

P2：更多器官与微观细胞、精美转场和更多课程。在时间不足时依次裁剪 P2→P1，不允许裁剪最基本自由探索+引导教学+两条真实贯通路线。

**明确不做**：原寝室场景游戏、人物漫游、角色日常模拟、虚构医学参数预测、医疗诊断、从零重建所有人体器官、全面真实组织体渲染、全器官全细胞强行覆盖、AI聊天、用户登录/复杂后端、无授权模型拷贝、用截图冒充实时交互。

## 5. 页面美术与体验标准（同步开发，不能后补）

**总体参考：**Claude/Kimi/Apple的暖白、近黑、出版物排版、克制层级；Messenger/Abeto、Nomadic Tribe的清晰视觉主角与空间镜头表现；《孤山独影》的温和漫画氛围可适度借鉴，但**不要把医学模型改造成科学结构不准确的玩具**。AgriScope是已实现的最佳本地设计规范参考。

**建议初始视觉基线**（以实际参考研究后适度调整）：暖纸色 `#F7F5F1`，近黑 `#1A1917`，柔暖灰，器官/系统用少量有语义的强调色；展示标题可采用系统可用的中文宋体/衬线，正文系统无衬线，技术标记少量等宽字体；大片留白，视觉主角始终是3D对象；细线划分信息，不堆叠浮夸卡片；禁止蓝紫霓虹科技大屏、廉价玻璃拟态、满屏Glow、无意义动态粒子、千篇一律AI渐变与假大空文案。

桌面舞台建议：顶部稳定品牌/模式/返回，左侧少量层级导航，中央主要3D舞台，右侧渐进式科普说明；移动端：3D舞台优先、底部抽屉/手势明确、触摸区域≥44px、避免固定3栏溢出。真实设计须在浏览器逐屏验证，不可只靠CSS猜。

**统一动画语义：**hover仅提示可点；selection表明当前结构；route表明进/退；camera显示从人体到器官的空间连续性；scale跨模型时采取**镜头推进→遮罩/匹配淡化→加载另一3D模型→提示尺度变化**，不要承诺几何连续真实穿越。所有动画可取消/中断；未加载完成时给真实进度或明确loading状态；`prefers-reduced-motion` 下瞬时转场；加载失败或WebGL不支持时提供文本/图片降级。

**特别参考 AgriScope 的现役原则**：交互意图明确、标题字号有限档位、统一motion token、返回保持状态、无意义动画删除、单Canvas生命周期**按实际渲染器契约实现**。注意 Vanatome 与 CellScene 各自可能自带Canvas，初版可在切换时完整卸载前者再挂载后者；禁止“为了单Canvas理想”强行侵入两个库导致工程失控。**同一时刻活跃WebGL场景尽可能只有一个**。

## 6. 技术架构与数据契约（可根据实际源码微调，但不能省略核心职责）

- 现有 `body-day/` 主工程作为唯一可构建应用；沿用当前可兼容的 React 19、TypeScript、Vite、Three/R3F/Drei。新增库前核实 peerDependencies、Node 版本、包体、许可证与用途；不要无理由把整个应用迁至Next.js。
- **建议模块职责**：`app/`（路由与外壳）、`domain/`（类型、ID、科学关系）、`features/anatomy/`、`features/organ/`、`features/cell/`、`features/learning/`、`features/explore/`、`features/report/`、`data/`（结构化内容/来源）、`design/`（tokens、motion、组件样式）、`services/assets/`（加载状态/版本/版权）、`tests/`。按现状可调整路径，不盲目复制目录树。
- **三维Adapter协议建议**：统一接口包含 `load(objectId)`、`focus(objectId)`、`select(objectId)`、`reset()`、`setMode(mode)`、`dispose()`，并拥有 `status:error|loading|ready`、`selectedId`、`renderableStructureIds`；具体View组件使用属性/钩子而非强制命令式；适配器负责将原项目结构ID映射成BodyDay ID。任何焦点操作必须先确认 ID 在真实模型 metadata 中存在，禁止写死猜测ID如 `heart` 不校验即调用。
- **关系实体**：`BodyEntity {id, nameZh, nameEn?, kind: body|system|organ|tissue|cell|organelle, modelAssetId?, summary, labels[], sources[], reviewStatus}`。`KnowledgeRelation {fromId, toId, relationType, description, sourceIds[], confidence?, reviewedAt?}`。额外 `GuidedLesson {id, title, goal, steps, questions, sourceIds}` 与 `SourceRecord {publisher,title,url,accessDate,license?,scope}`。全部纯数据、可验证、可扩展；分类本体的规范ID和模型本地ID分开存储。
- **导航状态**：`mode(explore|learn)`、`scale`、`selectedEntityId`、`selectedSystemId`、`selectedOrganId`、`selectedCellId`、`selectedStructureId`、`breadcrumbs`、`history`、`returnContext`、`lessonStep`、`loading/error`。刷新后URL恢复有效视图；浏览器前进/后退与面包屑一致，不产生死循环。
- **数据可用性**：并非所有器官有对应细胞模型。对未覆盖的节点提供清晰“可阅读知识/尚无3D微观模型”反馈；不强行跳入不相关模型；场景不完整时可用有来源的2D图示并明显标为“示意图”。
- **静态优先**：课程、关系、科学文本均可随包本地化，浏览器离线/弱网仍能有关键科普内容；不要为轻量学习记录新建数据库；后端不是P0。若CDN依赖模型资源，做可靠CORS/超时/错误处理，评估关键模型自托管并遵守署名义务。
- **性能**：逐系统按需加载、异步取消过时请求、缓存/压缩GLB、轻量过渡占位、DPR档位、渲染需按需激活、切换后回收GPU资源；高负载模型先做可用的合法替代模型。不得让主页面因任何一个模型错误白屏。

## 7. 科学性、内容原创、医学边界

1. 科普方向始终是**健康科普**，不仅是解剖术语。每条路线具备“器官/细胞如何工作→与健康行为或常见健康问题有什么关系→可以采取什么有依据的行动/认识”的通俗解释。保留知识适用边界，不宣传偏方或诊断建议。
2. “大脑→神经元”表示神经组织相关细胞，并非所有脑区只有一种神经元；“脾脏→白细胞”是免疫器官与细胞功能关联；“心脏→白细胞”是循环输送关系，**白细胞主要在骨髓产生而不是在心脏生成**；“胰腺→免疫细胞”在1型糖尿病等明确语境下才讨论。
3. 核心健康知识、选择题答案与解释要含来源ID。对有争议、版本差异、源未找到的细节不用“AI生成百科事实”补洞，标为待核，不进入正式科普正文。测验应理解机制而非记住无用数字。
4. 不呈现医学级精准“人体内部连续缩放”，不声称微观模型与器官几何在空间坐标上严格配准；在需要处标明“科学示意/模型不按真实比例”。
5. 不把程序化模型说成病理实测，不把演示动画说成真实免疫反应实时仿真。中文词语准确、统一、简明，用户可以从模型点击回到知识证据。

## 10. 分歧决策与故障降级规则（不得反复提问阻塞）

1. 如果主选Vanatome官方资产加载失败：先检查真实catalog URL、CORS、Node/版本、模型资源路径；短时修复无效则切换Human Atlas的合适可用实现，不去重新制作人体。
2. 如果Open Anatomy Studio整套组件难适配：只复用合法独立GLB与内容配置，使用主工程现有R3F的通用GLB viewer展示，不迁Next。
3. 如果某个细胞GLB无明确许可或文件过大：选有授权的NIH来源、程序化几何或轻量合法替代；保留科学示意边界。
4. 如果透明材质和真实模型冲突：牺牲华丽材质，不牺牲医学结构正确性或操作可用性。
5. 如果连续真实3D深潜不可行：使用“聚焦→遮罩→换模型→尺度标签”的语义连续转场；不虚构空间配准。
6. 如果15页与视频同时赶不上：优先保留≥10个有真实学习价值的页面、3个科普主题、两条可交互深潜链以及视频/文档；裁掉高级搜索、对比、多余动效和第三方大型素材。剩余阻塞列清楚。
7. 如果没有真实本地参考库：记录无法读取的路径，尽量利用AgriScope的可访问远端文档继续开发；不因缺少参考路径中断整个任务。
8. 如果没有推送权限：完整保存本地Git分支、可运行源码与交付包，并报告Git错误；不采用危险权限绕过。
9. 发现许可不清、医学事实不可靠、无法复现实测的内容时，宁可换可用来源/降低展示范围，也不把不实内容写进最终作品。
10. 每个阶段自行交叉核对：源代码/API是否存在→本机是否正常运行→浏览器效果是否符合定义→科普逻辑是否准确→版权是否允许→是否满足大赛材料。发现矛盾，以上游真实文件/官方附件/测试记录为准。

## 二、本地运行

```bash
cd body-day

npm install

# 开发模式（带 HMR）
npm run dev

# 生产构建 + 本地预览
npm run build
npm run preview
```

验证结果：

- `npm run build` 通过：`tsc -b` 无类型错误，`vite build` 产出 `dist/index.html` 0.82 kB、`dist/assets/index-*.css` 6.34 kB、`dist/assets/index-*.js` 1,258.40 kB（gzip 345.87 kB）。

## 三、画面参考与实现取向

参考作品：Make Me Pulse 2019、Messenger Web Game、Sable。

取其共同特征并落实到本 Demo：

- **艺术化的小范围第三人称探索空间**——不给"房间盒子"，而给"一眼能读完的娃娃屋构图"。
- **大色块 + 手绘感的 Toon 分级**——全场景共用一个 4 阶 `DataTexture` 渐变贴图，阴影不做软糊过渡，保留手绘的块面感。
- **统一描边**——程序化几何与角色使用 `<Outlines>` 反向外扩描边，暖棕色（`#4a3226`）而非纯黑，避免卡通变廉价。
- **克制的生活细节**——桌面文具、床上笔记本、地毯、绿植、衣帽架外套、墙面海报，让空间"有人住"。
- **缓慢环境动画**——云漂移、外套微摆、角色待机呼吸与转头，均为低开销的常量级计算。

明确避开的反例：Minecraft 方块风、默认 Three.js 几何演示、写实建筑可视化、Unity 素材默认场景、无美术设计的白盒子房间。

## 四、已实现功能

### 1. 场景结构

- 地板（程序化木纹 Canvas 贴图 + 重复平铺）、四面墙（上段浅米色 / 下段暖沙色 + 踢脚线）、无天花板。
- 后墙：**窗户**（木框 + 窗台 + 可透视的窗外景观）与**出口门**（木质门扇 + 门框）。
- 左墙：**卫生间门**（薄荷绿门扇，与寝室出口在视觉上区分）。
- **按相机隐藏近侧墙**：相机绕到哪一侧，靠近相机的那两面墙自动隐藏，保证任何时候都能看清房间内部与两扇门。

### 2. 家具与生活物件

| 类别 | 内容 |
| --- | --- |
| 睡眠区 | 单人床 + 青色被子（含翻折被沿、垂落被角）+ 陶土色靠枕 + 床上笔记本电脑 |
| 学习区 | 书桌 + 书桌椅 + **台式显示器**（程序化建模，屏幕为自发光面）+ 键盘 + 鼠标 + 台灯 + 书本 + 马克杯 |
| 收纳区 | 书架（含分层书本与摆件、柜顶纸箱）+ 床头柜（含小盆栽与书） |
| 生活区 | 地毯、卫生间/出口地垫、落地绿植、垃圾桶、衣帽架、书桌椅上的背包 |
| 墙面 | 两张程序化绘制的风格化海报（日出山丘 / 抽象几何） |

**电脑是场景中的明确焦点**：显示器放在书桌正中偏左，屏幕内容为程序化绘制的"深夜写代码"界面（窗口条、行号栏、彩色代码行、光标），夜间自发光显著增强，可直接复用于后续夜间剧情。

### 3. 窗外景观

- 程序化天空渐变（白天暖蓝天 / 夜晚深蓝 + 星点）。
- 草地剪影、多棵树（白天绿色 / 夜晚深色剪影）、远处建筑体块（**夜间随机窗户亮灯**）。
- 缓慢漂移的云带。
- **阳光只从窗户进入**：屋顶用不可见平面投影，使阳光在室内形成窗形光斑，而不是均匀照亮整间房。

### 4. 光照与昼夜

- 白天：暖色主平行光（晨间角度）+ 天光环境光 + 窗边柔和补光，产生合理接触阴影；户外明亮。
- 夜晚：天空与户外转深蓝，主光减弱，室内台灯与壁灯暖光亮起，显示器屏幕冷光更明显，形成室内暖光池。
- 昼夜切换为**平滑过渡**（灯光强度与材质亮度均使用指数阻尼），不是硬切换。

### 5. 角色与移动

- **程序化风格化大学生角色**：连帽衫（含口袋 / 帽子 / 领口）、裤子、鞋、头发、眼睛，统一描边。
- 待机动画：呼吸起伏、轻微转头、手臂微摆。
- 走步动画：双腿/双臂交替摆动、身体上下起伏、躯干前倾。
- 移动：WASD / 方向键，**相对相机方向**；`Shift` 奔跑；角色**平滑转向移动方向**（走最短弧）。
- 碰撞：圆形玩家 vs AABB 障碍，按轴最小位移推出并沿墙滑行，**不穿墙**，并对床、书桌、书架等大件家具做阻挡。

### 6. 相机

- 第三人称**斜俯视 3/4 构图**，默认一屏看清角色、床、书桌、电脑与两扇门。
- 鼠标拖拽环绕、滚轮拉近拉远（带角度与距离上下限）。
- 注视点与相机位置均做指数平滑跟随，不跟随生硬；注视点高度适配角色身高。

### 7. 交互（仅两处，按要求）

- **卫生间门**：走入半径内，门口浮起指示标记并出现提示「按 E 交互 · 卫生间门」；按 `E` 弹出「要刷牙吗？」，可选「刷牙 / 不刷牙」，选择后弹出结果提示条；`E` 与按钮均可关闭。
- **寝室出口**：走入半径内出现提示「按 E 交互 · 寝室出口」；按 `E` 弹出「准备前往食堂」，可选「确认出发 / 留在寝室」。
- 交互点采用"进入/离开只回调一次"的探测方式，避免每帧触发 React 重渲染。
- 弹窗打开时自动冻结移动输入，防止按键残留导致继续走动。
- 床、电脑、书桌不设交互（按任务书要求）。

### 8. 界面（中文 HUD）

- 左上角：时钟（白天 `08:30 · 清晨` / 夜晚 `23:10 · 深夜`）。
- 右上角：**生理状态 80/100**、**心理状态 80/100**（带对应色条）。
- 底部：操作提示（`WASD` 移动 / `拖拽` 转视角 / `滚轮` 远近 / `E` 交互 / `T` 昼夜）。
- 昼夜切换按钮：胶囊形按钮 + 指示灯，非默认 HTML 按钮样式。
- 交互提示条、结果提示条、弹窗、加载层均为定制样式；配色取自场景统一色板（米白纸感面板 + 暖棕文字 + 陶土色强调），与 3D 画面协调。

## 五、未完成功能

按任务书的边界，以下内容**不在本次范围**，明确未实现：

1. **卫生间内部场景**——只有门与门口交互，门后没有可进入的卫生间空间。
2. **刷牙科普动画 / 任何科普动画系统**——只到"选择刷牙或不刷牙 + 文字反馈"为止。
3. **食堂场景与前往食堂的流程**——「确认出发」只给出文字提示，不切换场景。
4. **完整游戏流程 / 剧情系统**——没有昼夜时间推进、没有事件驱动、没有存档。
5. **数据系统**——生理/心理状态为固定展示值（80/100），未接入任何计算或变化逻辑。
6. **角色骨骼动画文件**——为保证风格与色板的完全统一，角色为程序化建模，动画由代码驱动（待机/走步），未使用外部骨骼动画包；因此没有跳跃、坐下、开门等动作。
7. **后端 / 数据库 / 登录 / 多人 / 复杂物理**——按要求均未实现。
8. **移动端触屏操作**——UI 已做响应式布局，但未实现虚拟摇杆。

另需说明两处范围取舍：**窗帘**当前只有窗户两侧的固定布艺帘（几何体 + 描边），未实现"夜间自动拉合"的动画；**窗户**为固定窗扇，不可开关。

### 6.2 项目自制的替代项（不含第三方许可）

以下内容**未使用任何第三方资产**，为程序化建立或代码绘制，因此无外部许可证约束：

- **房间结构**：地板、四面墙、天花板投影面、踢脚线、门框、门扇、窗框、窗台 —— 由基础几何体构建。
- **台式显示器**：Kenney 的 `computerScreen.glb` 是单 mesh + 图集，无法单独驱动屏幕面自发光，故改为程序化建模（底座 / 支臂 / 圆角外壳 + 独立屏幕面 + 点光源）。
- **角色**：程序化风格化大学生（连帽衫、裤子、鞋、头发、眼睛）。
- **靠枕、被子（含翻折与垂角）、马克杯**：程序化几何体，用于替换原模型中与本项目色板冲突的珊瑚红软垫。
- **全部贴图**：木地板纹理、显示器屏幕内容、两张墙面海报、天空渐变（含星点）—— 均为运行时 Canvas 程序化绘制。
- **窗外景观**：草地、树木、建筑剪影、云带 —— 程序化几何体。

## 八、最重要的验收结论

打开页面第一眼看到的是：暖色调娃娃屋构图的小房间、青色被子的床、亮着屏幕的书桌、两扇清晰可辨的门、窗外有景、地面上有角色的接触阴影与光源方向一致的阴影——**是一个有美术设计的独立游戏场景，而不是 Three.js 几何演示**。

# BodyDay · H5 页面索引与逐页截图（H5_PAGE_INDEX）

> 赛事要求 H5 交互式作品「页面不少于 10 页（含封面、封底），总页面控制在 20 页以内」。
> BodyDay 按 **11 页**交付（含首页 `/` 与封底 `/about`），每个页面都可独立直达、可单独截图。
>
> 全站只有**一种探索体验**：中央唯一的三维人体（本作品自建 React Three Fiber 舞台渲染的
> Z-Anatomy 整具人体，模型随作品发布在 `public/models/`），右侧一条随选中联动的知识纸条。
> **没有「自由探索 / 引导教学」模式开关，也没有左侧常驻结构目录**；结构的选择完全交给模型本身
> （点选、悬停高亮、聚焦、隔离、**V2.1 滚轮驱动的逐层拆解**，以及「返回上一级」的层级栈）。
> 人体 → 系统 → 器官 → 细胞之间的差别，只体现为**镜头位置与右侧纸条内容的变化**，
> 不换页面外壳、不重挂三维场景。
> **2026-10-18**：顶栏为**五项层级导航（身体 / 系统 / 器官 / 细胞 / 关于）**，五项均落真实路由（实测 `navCount = 5`，见
> `delivery/test-evidence/verify-entry-sheet.json`）；入口为**同节点形变**；任意可点选结构都出**真实卡**。本节页面清单与 `body-day/src/app/routes.ts` 的 `PAGE_INDEX` 一致（11 页）。
>
> 全部截图由真实浏览器（Chrome for Testing + SwiftShader 软件渲染）在 **1440×900** 视口下对
> **真实运行的开发服务器**抓取（移动端一帧为 390×844，2x），
> 路径见 `delivery/test-evidence/screenshots/`（**14 张截图，V2.1（2026-10-16）按新界面重新采集**，逐张对照见 §2；
> 另有中性化视觉核对截图 10 张在 `…/screenshots/public-presentation/`）。
> 抓取时间：2026-10-15，V2.1 重采于 2026-10-16（本机时间）。

## 3. 逐页「该页能做什么」

| 序号 | 该页能做什么 |
|---|---|
| 01 首页 | 先显示完整独立的启动封面，封面内是真实字节进度；模型真正就绪后出现「进入探索」。点击进入后呈现完整人体，可转动、点选与逐层拆解。**不自动进入、不自动淡出**；加载超过 45 秒会提示检查网络并提供「重新加载」。 |
| 02 人体总览 | 不经封面可直接深链进入。转动完整人体；**V2.1：用滚轮**向下逐层拆解、向上反向组装（桌面端不再显示拆解滑杆，触屏保留）；点模型上的结构即高亮并聚焦（其余结构淡化而非隐藏），右侧纸条随之更新。 |
| 03 神经系统 | 人体中只显示神经系统，点选其中任一结构即可聚焦并查看知识。 |
| 04 循环系统 | 人体中只显示循环系统，真实结构可逐个点选。 |
| 05 淋巴系统 | 人体中只显示淋巴系统，真实结构可逐个点选。 |
| 06 大脑 | 镜头聚焦大脑（`cerebrum`），其余结构隐去便于观察；右侧给出脑的结构知识、健康关联，以及「进入神经元」的真实链路入口。 |
| 07 心脏 | 镜头聚焦心脏；右侧说明四腔 / 瓣膜 / 循环功能，并澄清「心脏 — 白细胞」是循环输送关系（心脏不生成白细胞）。 |
| 08 脾脏 | 镜头聚焦脾脏；右侧说明淋巴器官的免疫角色与血液过滤功能，以及「查看白细胞」（免疫功能关联）的入口。 |
| 09 神经元 | 细胞层程序化原创几何：胞体 / 树突 / 轴突 / 髓鞘，点选部件右侧知识联动。 |
| 10 白细胞 | 细胞层程序化原创几何：细胞膜 / 细胞质 / 细胞核，并说明白细胞主要生成于骨髓。 |
| 11 关于 · 数据与方法 | 作品定位、结构化数据规模、完整来源表（19 条，含访问日期与实测可达性）、模型与许可（CC BY-SA 4.0 的署名与标明修改）、科学免责声明（含拆解口径的边界说明）、11 页页面索引表。可打开原始来源链接、回到任意入口。 |

> 人体 / 系统 / 器官页的结构直接在模型上点选，不使用独立热标层；细胞页的部件热点为普通 DOM 投影。

## 4. 页面计数说明（供评委核对）

- 上表 11 行即 BodyDay 对外声明的 **11 个页面**，首页与封底计入其中。
- 其中 03 / 04 / 05（系统）、06 / 07 / 08（器官）、09 / 10（细胞）是各自独立的直达路径，
  但**共用同一个工作台组件与同一条右侧纸条**，差别只在镜头位置与纸条内容。
  它们不是「换一套外壳的新页面」，也不各自重新加载三维场景。
- 系统页以参数化路由 `/systems/:id` 提供，同一版式下可覆盖全部解剖系统；对外声明的页面数仍为 11。
- 关于「20 页以内」：BodyDay 声明为 **11 页**，满足「不少于 10 页」且远低于 20 页上限。
- 页面索引同时内置于封底 `/about` 表格中，可按行逐条核对。

## 5. 截图与录像复现方式

```bash
cd body-day
npm ci                             # 安装依赖（首次）
npx vite --port 5175 --strictPort  # 专用自测端口（不占用日常预览端口 5173）
# 另开终端，在 body-day/ 下运行截图与录像脚本：
node scripts/capture-screenshots.mjs   # 生成 14 张 PNG 到 delivery/test-evidence/screenshots/
```

脚本用真实浏览器走「封面 → 进入 → 旋转 → **滚轮逐层拆解 / 组装** → 选器官 → 进入器官页 → 下潜细胞 → 关于」的完整链路，
同一次运行内产出 14 张截图；体验录像的原始 webm 写在系统临时目录，再用 `ffmpeg` 转成交付用 mp4
（`delivery/demo/bodyday-v2-walkthrough.mp4`，**成片约 105 秒**（`ffprobe` 实测 105.4 s）；⚠️ 旧版所写「81 秒」为过期说法，已订正）。整具人体模型随作品发布在 `body-day/public/models/`，
截图与录像**不再依赖外网 CDN**，离线也能复现；细胞页面为程序化几何本地生成，同样无网络依赖。

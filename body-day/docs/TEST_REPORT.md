## 4. 真实浏览器验收（Playwright + Chromium 140，SwiftShader 软件渲染）

对**运行中的开发服务器**走真实链路（`node scripts/verify-v2.mjs`），用**相机投影出的真实屏幕坐标**点击具体器官，
读数由舞台自己通过 `onProbe` 上报，不靠肉眼判断。全程**控制台 error 与 pageerror 数量：0**。

### 4.1 启动闸门

| 读数 | 值 |
|---|---|
| 首屏封面状态 | `loading` → `ready`（真实字节进度） |
| 进入前外壳是否被屏蔽 | `inert = true`（不可点击、不可聚焦、不可读屏） |
| 就绪信号 | 舞台上报「装配完成 + 首个有效帧」后封面才出现「进入探索」 |
| 就绪耗时（本地资产） | **0.61 s ～ 1.24 s**（改为本地资源之前，从 CDN 加载时为 22.4 s） |
| 进入后 | 封面卸载、`inert = false` |

封面不自动进入、不自动淡出；加载超过 45 s 会提示检查网络并给出「重新加载」。

### 4.2 拆解（真实几何位移）

| 进度 | 可见网格数 | 外壳不透明度 | 说明 |
|---|---|---|---|
| 0% | 984 | 1.000 | 完整人体，皮肤不透明 |
| 25% | 984 | **0.316** | 皮肤渐进半透明，内部结构开始显现 |
| 50% | **748** | 0 | 外壳（236 网格 = 984 − 748）已移出可见集合与射线层 |
| 100% | 748 | 0 | 各解剖层径向分离，整体仍在画面内 |

- 位移量由 `progress` 重新计算并覆盖（**从不累加**），纯函数测试覆盖「反复 0→1→0→1 不累计偏移」；
- 镜头随**位移后的整体包围盒**联动取景（实测镜头距离 3.05 → 3.25），完全拆解时人体整体仍留在画面内。

### 4.3 拆解后仍可点选

按投影坐标点击，**一次命中**：

| 场景 | 命中结果 | 面板读数 |
|---|---|---|
| 拆解 50% → 点心脏 | 命中 | 完整心脏知识卡 + 「你点到的是「Right_ventricle」，它归属心脏」 |
| 拆解 100% → 点脾脏 | 命中 | 完整脾脏知识卡 + 「当前结构：脾脏」 |

装配态（未拆解）点击人体，命中的是体表外壳 `body-shell`（皮肤确实挡在前面），
面板如实显示「体表（皮肤）· 体表与区域解剖」，并写明 BodyDay 没有为它单独编写内容，**不拿别的结构顶替**。
按 `Esc` 取消选中并回到本页默认取景；拆解程度在页面内保持不变。

## 5. 未完成的验证（如实记录）

1. **移动端未做真机验收**：响应式布局已在浏览器视口（390×844）下检查无横向溢出，
   但**没有 iOS Safari / Android Chrome 的真机 / 模拟器截图验收记录**。
2. **真实 GPU 帧率未采集**：本机验证使用的是软件渲染（SwiftShader），
   不能代表真实显卡性能，因此**本报告不给出任何 FPS 或性能分数**。
3. **拆解的产品级视觉分离仍在打磨**：分层位移与外壳渐进隐去已落地并实测可见，
   但内部层间距仍可继续加大（当前每层额外位移 = 人体包围盒半径 × 0.17）。
4. **多版本浏览器兼容性仅覆盖 Chromium 140**：Firefox / Safari 未做实测。
5. **作品尚未在任何平台提交**（赛事截止 2026-10-18）。

这些缺口不影响已声明功能的可用性，但**不声称已完成**。
